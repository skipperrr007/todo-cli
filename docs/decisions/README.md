# Decisions

本目录记录已经接受、会长期影响架构、接口、默认值、安全或运维方式的重要决策。

## 何时创建 decision

适合创建：

- 选择或替换核心架构；
- 改变公共接口、数据模型或兼容性政策；
- 选择重要外部依赖；
- 改变安全、部署、持久化或默认行为；
- 接受一个存在明显替代方案和长期后果的取舍。

不必创建：

- 普通缺陷修复；
- 不改变长期行为的重构；
- 临时实验；
- 尚未接受的想法；
- 提交、review 和执行日志。

## 编号与生命周期

文件使用 `NNNN-short-title.md`。复制 `0000-decision-template.md` 后分配下一个编号。

生命周期建议为：`proposed`、`accepted`、`deprecated`、`superseded`。只有 `accepted` decision 能作为当前决策权威。若决策改变，新建 decision，并双向链接替代关系，不覆盖旧文件。
