# Codex Collaboration Guide

本指南解释项目结构如何帮助 Codex 快速接手。具体代理命令和权限规则以根 `AGENTS.md` 为准。

## 最小上下文包

Codex 开始普通任务时，不需要先读取全部仓库。固定最小上下文包是：

1. `config/project.json`：这是模板还是派生项目；
2. `AGENTS.md`：允许和禁止的行为；
3. `README.md`：项目目的和最短入口；
4. `CONTEXT.md`：术语、能力边界和长期不变量；
5. `docs/README.md`：事实 owner 和阅读路由；
6. `docs/handoffs/current.md`：当前目标、停止边界和下一入口；
7. 当前任务直接关联的源码、测试和文档。

这套入口同时服务新会话、上下文压缩恢复和新协作者接手。

## Codex 应建立的工作摘要

采取动作前，Codex 应能用简短内容回答：

- 当前仓库角色是什么？
- 项目解决什么问题？
- 当前唯一主要目标是什么？
- 本次任务涉及哪些目录和 owner 文档？
- 哪些后续动作不在授权范围？
- 完成后运行哪些检查？

不要求每次都向用户重复整套摘要，但不能在这些问题尚不清楚时进行高影响修改。

## 让状态保持可接手

- `README.md` 保持稳定，不记录每日进展。
- `CONTEXT.md` 使用当前时态，删除被取代语义。
- `docs/handoffs/current.md` 只保留当前仍影响下一位开发者的状态。
- 重要设计进入 decision 或 architecture，不藏在聊天记录中。
- 操作命令进入 runbook，并写明前置条件、退出判定和风险边界。
- 里程碑完成后更新 current handoff；历史流水按价值归档或删除。

## 平台边界

模板依赖项目内 `AGENTS.md`，不依赖用户级 memory、skill 或 `.codex/` 配置。项目可以后来增加这些能力，但必须保持：

- 缺少个人配置时，仓库仍可被另一位 Codex 或人类接手；
- 项目事实保存在 Git 跟踪的项目文档中；
- 用户偏好和凭据不写入项目仓库；
- 平台专属入口不得复制并漂移根级项目规则。
